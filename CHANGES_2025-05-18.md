# MSSQLCollector → добавлена поддержка OceanBase + JSON-формат результата

_Дата: 2025-05-18_

## Что добавлено

1. **OceanBase (MySQL-режим)** теперь поддерживается во всех трёх местах:
   - `ServersSource` — читать список инстансов из OB
   - `JobsSource` — читать список запросов из OB
   - `ResultsDestination` — писать результаты в OB

2. **Формат результата** теперь переключается через `<ResultFormat>XML|JSON</ResultFormat>`
   в `<ResultsDestination>`. Используется и для `LOCALFILE`, и для `MSSQL`, и для `OCEANBASE`.

3. **Тип СУБД на уровне инстанса**: в `InstanceConfig` добавились поля
   `DbType` (`MSSQL` | `OCEANBASE`), `Tenant`, `Cluster`. Все три опциональны.
   Без них всё работает как раньше (дефолт = MSSQL).

## Обратная совместимость

- Существующие конфиги с `<Type>MSSQL</Type>` работают без изменений.
- Существующие XML-файлы инстансов без `<DbType>` работают как MSSQL.
- Если в `<ResultsDestination>` нет `<ResultFormat>` — для MSSQL берётся XML (как раньше),
  для OCEANBASE автоматически JSON.

## Что нужно сделать в проекте

### 1. Положить mysql-connector-j в `lib/`
Например, `lib/mysql-connector-j-8.4.0.jar`. После этого в IntelliJ:
**Project Structure → Modules → Dependencies → + → JARs or directories → lib/<file>.jar → Scope: Compile.**

Или вручную поправить `MSSQLCollector.iml` — добавить второй блок `<module-library>`
по аналогии с существующим `mssql-jdbc-12.10.1.jre11.jar`.

### 2. Скопировать обновлённые файлы поверх существующих
Структура папок в `/mnt/user-data/outputs/src/` совпадает с проектом.

### 3. Создать таблицы в OceanBase (если будете писать туда результаты)
См. `sql/oceanbase_schema.sql`. Минимум — таблица `admintools.ResultProcessorLog`.

### 4. Подправить конфиг
Готовые шаблоны:
- `config/MSSQLCollectorConfig.OB-dest.example.xml` — серверы и задания из MSSQL,
  а результаты в OceanBase.
- `config/MSSQLCollectorConfig.OB-all.example.xml` — всё через OceanBase.
- `config/InstancesConfig.mixed.example.xml` — пример локального XML
  со смешанным парком MSSQL + OB.

## Ключевые нюансы, которые стоит знать

### Логин для OceanBase (MySQL-режим)
В OB логин для тенанта имеет формат `user@tenant#cluster`. В коде это собирается
автоматически:
- если в `<UserName>` уже стоит строка с `@` — она используется как есть;
- иначе склеивается `userName + '@' + tenant`, и если есть `cluster` — `+ '#' + cluster`.

В JDBC URL символ `#` нужно экранировать как `%23` (это URL-encoding):
```
user=collector@business_tenant%23obcluster
```

### MSSQL Enricher не применяется к OceanBase
В `AppConfigReader` MSSQL-параметры (`encrypt=false;trustServerCertificate=true;
multiSubnetFailover=true;applicationName=...`) теперь добавляются только если
`<Type>` — `MSSQL` (или пуст). Для `OCEANBASE` строка подключения берётся как есть.

### Драйвер OceanBase
Используется `com.mysql.cj.jdbc.Driver` (mysql-connector-j 8.x). OB MySQL-режим
полностью совместим. Альтернативно можно положить `oceanbase-client` и поменять
имя класса драйвера в `DbType.driverClass()`.

### JSON-формат результата
Ровно такая структура, как было оговорено:
```json
{"ci":"CI00002","reqId":"PERF","rows":[
  {"sql_server":"srv1","source":"dm_os_performance_counters","metric_name":"…","instance_name":"…","metric_value":123},
  ...
]}
```
- Числовые SQL-типы → JSON-числа.
- NULL → `null`.
- Все остальные значения → JSON-строки с экранированием.

### Хранимая процедура vs INSERT
Существующая эвристика для распознавания «это имя SP, а не SQL» сохранилась:
если значение `<MSSQLQuery>` — одно слово (или `schema.sp`), вызывается через
`{call name(?,?,?,?)}`; иначе — как `PreparedStatement` с 4 параметрами:
`ci`, `reqId`, `body` (XML или JSON), `resultExec`.

Это значит, что для OB можно использовать обычный INSERT (так и сделано в DDL/примерах):
```sql
INSERT INTO admintools.ResultProcessorLog (ci, req_id, result_json, result_exec) VALUES (?, ?, ?, ?)
```

## Что НЕ сделано (можно при необходимости)
- Отправка результатов в Mongo — оставлена заглушкой, как было.
- Поддержка двухточечной автоконвертации datetime в JSON (сейчас даты приходят
  как строки в формате, который вернёт драйвер; ничего специального для timestamp).
- Если нужна обработка `OB → Prometheus` (т.е. сборщик данных из OB-инстансов),
  она уже работает: `InstanceConfig.dbType=OCEANBASE`, `Destination.type=PROMETHEUS`.
  PrometheusResultWriter не зависит от DbType — он работает с ResultSet.

## Быстрая проверка после интеграции

1. **Старый MSSQL-only пайплайн не сломан** — запустите с прежним конфигом.
   В логах при подключении должно быть `[DB] Connecting [MSSQL]: …`.
2. **OB destination** — выставьте `<Type>OCEANBASE</Type>` и `<ResultFormat>JSON</ResultFormat>`,
   проверьте `SELECT * FROM admintools.ResultProcessorLog ORDER BY id DESC LIMIT 5;`
   — в `result_json` должен лежать корректный JSON, `JSON_LENGTH(result_json,'$.rows')`
   должно совпадать с числом обработанных строк.
3. **OB source** — в логах при чтении должно появиться
   `InstancesConfigReader: loaded N servers from OCEANBASE.`
